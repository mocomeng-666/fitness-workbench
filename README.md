# 个人健身训练工作台

> Personal Fitness Workbench — 一个纯前端、零依赖、训练数据保存在本地的 8 周健身训练 PWA。

按 **8 周力量 + 有氧训练计划**组织训练的移动端网页应用：根据你的训练目标、每周可训练天数和身体情况自动排期，训练时记录每组重量与剩余次数，并按规则自动给出进阶建议（该加多重、今天要不要减量）。训练记录和体态照片保存在你自己的浏览器里，不注册、不登录。核心训练功能可离线使用；可选 AI 器械识别需要联网，并会将所选照片发送给你配置的服务商。

---

## 为什么做这个

这个项目从日常训练中的三个问题出发——**今天该练什么、加多少重量、身体不舒服时该不该停**，这三件事不需要云、不需要账号，只需要一个可靠的本地规则引擎。

所以这个工作台的目标很明确：

- **数据主权**：训练记录、体态照片全部只存在浏览器 IndexedDB，换设备靠导出文件，不经手任何服务器；
- **离线可用**：首次在线加载并完成缓存安装后，核心训练功能可离线使用，健身房信号差也照常记录；
- **决策自动化**：把"该练什么、加多少、要不要减量"交给规则引擎（双重进阶、状态减量、伤情规避），而不是靠记忆和感觉；
- **可分发、可署名**：训练周报可生成分享卡（可配置署名，如「XX的健身管家」），适合教练或会员服务场景发给学员；
- **零依赖可维护**：原生 HTML/CSS/JS，无框架无 npm，应用样式与逻辑内联到 HTML，另有离线缓存与安装配置文件，方便阅读和维护。

## 功能一览

底部五个页签 + 一个首次配置流程：

| 模块 | 能做什么 |
|---|---|
| **首次配置** | 采集身高、出生年份、训练目标（5 项单选）、每周训练天数（2/3/4/5）、身体情况（无伤/膝部有伤/其他部位有伤）、计划开始日期 → 自动生成 8 周排期预览，可确认或更换 |
| **今天** | 显示当天任务（力量日 / 有氧日）；力量逐组记录（重量、实际次数、剩余次数 RIR、组间休息计时）；有氧记录（项目、时长、主观强度 1–10）；顶部给出当日建议卡 |
| **计划** | 8 周日历总览，逐周逐天展示安排与完成状态；支持查看每周模板详情 |
| **进展** | 周完成率、连续完成天数、力量进步亮点、体重围度记录；一键生成周报分享卡（Canvas 出图） |
| **动作库** | 动作卡片列表 + 动作详情（要领 / 常见错误 / 部位提示 / 替代动作）；「换动作」自选替代；可拍照识别器械（可选能力，见下） |
| **设置** | 身体档案修改、训练偏好、外观主题、自定义有氧项目、分享卡署名、数据备份导出 |

**核心规则（产品灵魂）**：

- 力量日 A/B 两套模板根据周次与当周力量日顺序交替；力量与有氧天数按目标和每周可练天数生成，可在计划页调整；
- **双重进阶**：某动作连续两次达组数与次数上限且剩余次数充足 → 下次重量 +2.5kg（自重动作改为加次数/时长）；
- **状态减量**：按昨日睡眠、酸痛、精力自动给出「照常 / 减组 / 短时模式」建议；
- **伤情联动**：膝部有伤时自动规避高冲击下肢动作并展示 5 项红旗症状；其他部位有伤给「量力而行」提示；
- **三套皮肤**：奶油 / 莓果 / 暗夜，设置页即时切换。

## 用到的技术

**核心栈（全部原生，无运行时依赖）**

| 用途 | 技术 |
|---|---|
| 界面与逻辑 | 原生 HTML / CSS / JavaScript（ES6+，无框架、无打包器） |
| 本地数据 | IndexedDB（Promise 封装，库名 `fitness-workbench`） |
| 离线能力 | Service Worker + Cache API（Cache First，核心训练与文字动作说明可离线使用） |
| 应用安装 | Web App Manifest（PWA，可添加到主屏、全屏独立运行） |
| 分享卡出图 | Canvas 2D |
| 主题换肤 | CSS 自定义属性（CSS Variables）按 `data-theme` 覆盖 |
| 图标 | 内联 SVG data-URI（无需外部图片文件） |
| 构建 | Python 3 标准库（`build.py`，把 CSS/JS 内联成单文件） |
| 部署 | 任意静态托管（Cloudflare Pages / GitHub Pages / Netlify 等） |

**可选外部能力（BYOK，自带 Key，默认关闭）**

「拍器械识别」功能使用 OpenAI 兼容的视觉模型接口，用户在设置页自行配置，前端直连，照片只发往自选服务商：

- 智谱 AI（`glm-4v-flash`）
- 通义千问（`qwen-vl-plus`）
- 豆包（`doubao-1-5-vision-pro-32k-250115`）
- OpenAI（`gpt-4o-mini`）
- 或任意自定义 OpenAI 兼容接口（baseUrl + model 可填）

预设名称对应当前源码配置，不保证服务商持续提供这些模型；请按服务商实际支持情况配置模型与跨域访问。

**开发协作**：本项目由 WorkBuddy（AI 助手）与产品所有者协作开发，迭代过程沉淀为 `SPEC.md`（施工规格书）与 `docs/PRD_v2.0_source.md`（产品需求）。

## 本地运行

需要 Python 3 和现代浏览器。构建与本地服务只使用 Python 标准库，无需 npm 或 pip 安装依赖。Windows 没有 `python3` 时可替换为 `py -3`。

先获取代码：

```bash
git clone https://github.com/mocomeng-666/fitness-workbench.git
cd fitness-workbench
```

也可以在 GitHub 选择 **Code → Download ZIP**，解压后在终端进入项目目录。

**方式一：运行构建产物（推荐）**

```bash
python3 build.py
python3 -m http.server 8080 --bind 127.0.0.1 --directory dist
```

浏览器打开 [http://localhost:8080](http://localhost:8080)。终端保持运行，按 `Ctrl+C` 停止服务。不要直接双击 HTML：Service Worker 需要安全上下文，本机可使用 localhost，线上请使用 HTTPS。

**方式二：直接运行源码（仅用于调试）**

```bash
python3 -m http.server 8081 --bind 127.0.0.1 --directory src
```

打开 [http://localhost:8081](http://localhost:8081)。源码页的 CSS/JS 没有全部预缓存，不能作为完整离线验收环境；Cache First 也可能使刷新后仍显示旧文件。建议使用独立的浏览器测试环境并绕过 Service Worker 缓存，或使用方式一重新构建并更新缓存版本验证改动。

不同地址或端口拥有独立的本地数据。日常使用请固定访问同一地址。

**从零体验完整流程（仅限已备份或可丢弃的测试数据）**

访问带 `?reset=1` 的本地地址会立即清空该站点的档案、训练记录、测量、照片及设置，回到首次配置页，没有二次确认。使用前先导出所需备份。源码实际按 `reset` 参数是否存在触发，因此不要将任何带此参数的地址作为日常书签。

## 构建

```bash
python3 build.py
```

构建脚本做的事：

1. 把 `src/styles.css` 与 `src/data.js` → `db.js` → `engine.js` → `app.js`（固定依赖顺序）内联进 `dist/index.html`；
2. 拷贝 `src/sw.js`、`src/manifest.webmanifest` 到 `dist/`；
3. 每次重新生成 `dist/`，清理旧构建残留。请只修改 `src/`，不要在 `dist/` 中存放个人文件。

产物为 `dist/index.html`、`dist/sw.js`、`dist/manifest.webmanifest` 三个文件。HTML 已内联应用样式与脚本；部署时请保留三个文件的相对位置。

更新缓存版本：修改 `src/sw.js` 里的 `CACHE` 常量（如将 `fitness-workbench-public-v1` 改为 `fitness-workbench-public-v2`），然后重新构建并发布，让浏览器安装新版本缓存；必要时再次刷新页面等待接管。

## 部署

**Cloudflare Pages（可选）**

以下命令另外需要 Node.js/npm、Cloudflare 账号及部署权限：

```bash
npx wrangler pages deploy dist --project-name <你的项目名> --branch main
```

**GitHub Pages**

仅上传代码不会自动发布网站。以下方式需要 Git 写入权限和 Pages 配置：

```bash
# 若 dist/ 已纳入版本管理，可直接把该目录推到 gh-pages 分支：
git subtree push --prefix dist origin gh-pages
# 或直接将 dist/ 内的文件复制到 gh-pages 分支根目录后推送，
# 并在仓库 Settings → Pages 中选择该分支与根目录。
```

**其他**：Netlify / Vercel / 任意对象存储，直接上传 `dist/` 目录即可。

**安装到手机**：

- iPhone / iPad：Safari 打开 → 分享按钮 → 「添加到主屏幕」，之后从桌面图标全屏启动；
- Android：Chrome 打开 → 菜单 → 「安装应用」（或等待自动提示）。

## 数据与隐私

- 所有训练记录、身体数据、体态照片均存于**浏览器本地 IndexedDB**，应用本身没有任何后端接口；
- 首次加载和更新会请求网站静态资源；可选「拍器械识别」由用户主动配置并触发，所选照片发送给用户自选的模型服务商；
- API Key 保存在本机浏览器设置中，未加密；应用不内置密钥，不提供服务端代理；
- 备份导出：`设置 → 数据备份`，支持 JSON 记录导出（含档案、训练、测量与周报，不含照片、设置和 API Key）与照片 ZIP 单独导出；
- 换设备前请分别备份记录和照片；清除站点数据会丢失本地内容。不要把真实备份、照片、密钥或部署缓存提交到仓库。
