## 1. 产品定位与硬边界

### 1.1 一句话定位

一款**单机、离线可用、无账户**的个人健身训练工作台（PWA）：用户先回答「目标、每周可练几天、基础、膝况」完成个性化配置，系统给出**可逐天调整**的每周排期，训练日引导用户完成「练前状态 → 建议卡 → 逐组记录 → 练后反馈 → 下周建议」闭环；通过可解释的 **RIR + 双重进阶引擎** 提供每次训练的加减载建议，并用**奶油色卡片化界面 + 朋友式文案 + 周报分享卡**降低持续使用门槛。

### 1.2 目标人群与核心场景

- 希望规律运动的成年人，包括久不训练后重新开始的人群；身体情况由用户自行填写。
- 每周可训练 **2 / 3 / 4 / 5 天**的任意普通人（不再假设必须 5 天，含周末可练人群）。
- 核心场景：晚上健身房内 60 分钟力量或有氧训练；状态差时 25 分钟精简兜底；每周出周报并可一键生成分享卡。

### 1.3 产品形态与技术选型

| 维度 | 决策 |
|---|---|
| 形态 | 可安装的响应式 PWA（移动端优先，桌面适配） |
| 技术栈 | 纯原生 HTML / CSS / JS，零框架、零 npm 依赖、零 CDN 引用（必须离线可用） |
| 存储 | 浏览器 IndexedDB（库名 `fitness-workbench`，版本 1）；**禁止用 localStorage 存放训练数据** |
| 网络 | 无后端、无服务器；Service Worker Cache First 缓存应用外壳，安装后核心训练功能可离线使用；AI 识别需联网 |
| 构建 | 多文件开发（src/）→ `build.py` 内联为单文件交付（dist/）；sw.js 与 manifest 保持独立文件 |

### 1.4 硬边界（明确不做）

| # | 不做事项 | 备注 |
|---|---|---|
| B-01 | 账户、登录、注册、云同步 | 全部数据仅存本机浏览器；产品内任何入口不得出现此类代码 |
| B-02 | 健身房外活动记录 | 有氧器械仅跑步机 / 椭圆仪 / 登山机三选，无「户外跑」等选项 |
| B-03 | 饮食 / 热量估算激励 | 不计算消耗热量、不做热量激励 |
| B-04 | 心率等穿戴设备接入 | 强度用「说话测试」代替 |
| B-05 | 社交功能 | 无关注 / 评论 / 排行榜；分享仅限本地生成图片由用户自行决定去向 |
| B-06 | 医疗诊断 / 治疗性表述 | 所有建议 UI 标注为「建议」而非诊断；禁用 BMI 驱动减脂、单日体重焦虑式展示 |
| B-07 | 推送 / 红点 / 断签惩罚 | 无任何推送与红点，休息日不催练 |

### 1.5 差异化特征

1. **可解释的建议引擎**：每次建议卡 = 「结论 + 一句原因」+「为什么这样建议？」可展开，用户可接受或忽略（忽略留痕）。
2. **仪式感而非焦虑感**：完成 ✅ 庆祝动效、🔥 连续天数、第 8 周毕业卡；无负向激励。
3. **周报分享卡**：浏览器 Canvas 本地生成 1080×1350 PNG，默认不含体重与体态照片，可长按保存。
4. **朋友式文案**：所有建议卡、空状态、毕业文案集中管理（`data.js` 的 `COPY` 常量），语气温暖不说教。

## 4. 首次使用流程（Onboarding）

触发条件：本地无 `profile` 记录（`DB.get('profile','me')` 为空）。单屏多卡片自上而下呈现，底部一个「开始我的 8 周计划」保存按钮；字段顺序即交互顺序。

| 步骤 | 卡片内容 | 输入控件 | 默认值 / 校验 |

| S2 | 你首要的健身目标是什么？（单选） | 胶囊单选 ×5 | 默认「改善体态」；选项见 4.3 |

### 4.2 目标选项（单选）

问题文案：**「你首要的健身目标是什么？」**

| id | 标签 | 默认建议力量/有氧配比 |
|---|---|---|
| fatLoss | 减脂 | 有氧优先（见 4.4） |
| muscle | 增肌增力 | 力量优先 |
| posture | 改善体态 | 3 力量 + 2 有氧（默认选中） |
| energy | 提升精力 | 有氧优先 |
| habit | 恢复运动习惯 | 3 力量 + 2 有氧 |

训练基础选项：`experienced` 有训练经验 / `restart` 久不训练，重新开始（默认）。该字段与膝部情况仅入库备查，不改变排期与进阶规则。

### 4.3 建议排期映射（目标 × 天数，V1.2 核心）

生成原则：**天数越少力量占比越高（力量保本）；同一目标下天数变化只调整有氧天数；力量日不连续超过 2 天**。切换目标或天数时，已做的逐天自定义将被**重新生成覆盖**。

| 首要目标 | 2 天 | 3 天 | 4 天 | 5 天 |
|---|---|---|---|---|
| 减脂 fatLoss | 1力+1有氧：一力量、四有氧 | 1力+2有氧：一有氧、三力量、五有氧 | 2力+2有氧：一有氧、二力量、四有氧、五力量 | 2力+3有氧：一有氧、二力量、三有氧、四力量、五有氧 |
| 提升精力 energy | 同减脂 | 同减脂 | 同减脂 | 同减脂 |
| 增肌增力 muscle | 2力：一、四力量 | 3力：一、三、五力量 | 3力+1有氧：一、二力量、三有氧、五力量 | 4力+1有氧：一、二、四、五力量、三有氧 |
| 改善体态 posture | 2力：一、四力量 | 2力+1有氧：一力量、三有氧、五力量 | 3力+1有氧：一力量、二有氧、四、五力量 | 3力+2有氧：一、三、五力量、二、四有氧 |
| 恢复运动习惯 habit | 同改善体态 | 同改善体态 | 同改善体态 | 同改善体态 |

逐天编辑交互：每天三个胶囊按钮循环三态（💪 力量 / 🚶 有氧 / 😴 休息），选中态高亮对应类型色。计数提示（实时）：已选 N 个，还需恰好 X 个（提示「再加 n 天 / 去掉 n 天」）；当 N == X 且与建议排期有差异时，显示轻提示：`和建议的配比不太一样哦——没关系，适合你的节奏最重要，可以继续。`（可忽略，不阻塞）。

### 5.7 日期 → 模板解析规则（resolveTemplateId，随自定义排期工作）

对某天：取排期类型 `type ∈ {strength, cardio, rest}`，rest 返回空（休息日）。记 `pos` = 本周内该类型已出现的序号（含当天，从 1 起）。`oddWeek = (weekIndex 为奇数)`、`oddPos = (pos 为奇数)`：

- 力量日：`(oddWeek == oddPos) ? strengthA : strengthB` → 效果为 **A/B 隔周交替**（第 1 周按出现序 A、B、A…；第 2 周 B、A、B…），每周多个力量日时同周内也轮换 A→B→A。
- 有氧日：`oddPos ? tuesday : thursday` → 有氧内容（椭圆仪日 / 跑步机日）交替。

### 5.8 动作库（EXERCISES）字典规格

字段：`id / name(中文) / en(英文) / type / target / bodyweight(是否自重) / perSide(每侧) / timed(计秒,侧桥) / kneeCaution(膝部注意角标) / cues(要领数组) / mistakes(常见错误数组)`。

`type` 枚举：`free` 自由重量 / `machine` 固定器械 / `bodyweight` 自重 / `cable` 绳索 / `cardio` 有氧器械。`target` 枚举：`lower / upper / core / posture / cardio`。

动作全集（20）：哑铃高脚杯箱式深蹲、哑铃罗马尼亚硬拉、坐姿划船机、坐姿推胸机、自重臀桥、死虫、有支撑分腿蹲、坐姿腿弯举、上斜哑铃卧推、中立握高位下拉、绳索后束划船/反向飞鸟、侧桥、上斜肩胛俯卧撑、上斜俯卧撑、自重提踵、徒手髋铰链、胸椎旋转、胸椎伸展、靠墙滑手、仰卧/靠墙下巴回收，另有氧器械：跑步机快走、椭圆仪、登山机。

`kneeCaution=true` 的动作：哑铃高脚杯箱式深蹲、有支撑分腿蹲、登山机（执行页与动作库显示「膝部注意」橙角标 + 膝部规则提示，文案见 9.4 COPY.kneeRule）。

## 6. 规则引擎（engine.js）

### 6.1 RIR 定义

一组做完后**自己估计还能规范完成的次数**。选项枚举：`0 / 1 / 2 / 3 / 4 / 5+`（`5+` 归一化为 5 参与计算）。首次使用弹说明（COPY.rirHelp），点「知道了」后不再弹。

### 6.2 练前建议卡（readinessAdvice，按顺序叠加多条，可同时出现多条）

输入 readiness：`{sleepHours, energy1to5, fatigue1to5, kneePain0to10, sore, note}`；template 为今日模板。规则：

| 触发 | 建议 id | 结论（title） | 一句原因（detail） | 建议动作 |
|---|---|---|---|---|
| 膝部疼痛 ≥ 3 | knee | 膝部有点闹脾气 | 疼痛到 3 分以上啦，下肢今天不加重，换无痛动作或缩小幅度，上肢照常练。 | knee（下肢不进阶） |
| 睡眠 < 6 小时 且 今日为力量模板 | sleep | 昨晚没睡好吧 | 睡了不到 6 小时，建议主要动作保持重量、少做 1 组，别硬撑。 | reduceSet（主要动作减 1 组，组数 >1 时） |
| 精力 ≤ 2 或 疲劳 ≥ 4 | energy | 今天有点累呀 | 咱们轻松点，25 分钟精简模式搞定，动了就是赢。 | shortMode（全部动作组数压到 ≤2，模式置 short） |
| 明显全身酸痛 on | sore | 浑身酸痛对吧 | 今天不加重，辅助动作可以少做一点，恢复优先。 | sore（非主要动作减 1 组） |
| 以上均不触发 | plan | 状态在线，按计划来！ | 睡眠和精力都不错，正常执行就好。 | plan（唯一按钮「好」） |

建议卡 UI：标题加粗 + 原因（sub）+「为什么这样建议？」折叠（每条规则给一句大白话解释，见 COPY 第 9.4 节后注）+「接受 / 忽略」按钮（plan 只显示「好」）。**接受** = 应用建议动作到本次计划（存 appliedAdvice）；**忽略** = 记录 ignoredAdvice 留痕。顶部固定小字：`以下都是建议，不是诊断，你说了算。`

### 6.3 双重进阶（progressionAdvice：每次训练后为下次同动作生成建议）

输入：该动作全部历史记录（新→旧）、次数区间 [min,max]、动作字典。取最近一次有效组数据计算：`avgRir` = 各组 RIR 均值；`allAtUpper` = 每组次数均 ≥ 区间上限；`anyBelowLower` = 存在组 < 下限。决策表：

| 条件 | 动作类型 | 建议 |
|---|---|---|
| anyBelowLower | 负重 | 减量：下次减 2.5kg（最低 0），或减 1 组，或替换动作 |
| anyBelowLower | 自重 | 减少每组次数目标 / 缩短保持时长，先保证质量 |
| allAtUpper 且 avgRir ≤ 0.5 | 任意 | 保持：已达目标次数但 RIR≈0，待 RIR 回升再进阶 |
| allAtUpper 且 avgRir ≥ 2，**且连续两次**均达上限（上一次也 allAtUpper 且 RIR ≥ 2） | 负重 | **进阶 +2.5kg**（`下次至 Xkg`） |
| 同上连续两次 | 自重 | RIR ≥ 3 时「先增加每组次数或延长保持时长」；否则保持次数、待 RIR≥3 再加 |
| 达上限但仅一次 / RIR 不足 | 任意 | 保持，文案提示「连续两次达标后将建议加重」 |
| 其余 | 任意 | 按计划保持当前重量与次数目标 |

加重梯度全局 **2.5kg**（上肢下肢一致；自重动作永远走「加次数/时长」而非加重）。UI 用进度口径文案（如 `连续两次达次数上限且 RIR≥2：建议下次 +2.5kg（至 Xkg）。`），并始终以小字提示 `以下都是建议，不是诊断，你说了算。`

### 6.4 膝部安全与红旗

- **运行中膝痛 ≥ 3**（练前输入或动作异常反馈输入）→ 当日下肢不再进阶；动作异常反馈中疼痛 ≥3 弹「疼痛提示」：建议减重、缩小幅度或替换动作（建议，非诊断）。
- **红旗症状清单**（5 项，动作异常反馈与练后反馈两处勾选）：卡锁、明显肿胀、无法完全伸直、反复打软腿、持续加重。
- 命中红旗 → 弹「🛑 红旗症状提醒」页（深红）：`如果出现：膝关节卡锁、明显肿胀、无法完全伸直、反复打软腿、疼痛持续加重——先停一停，下肢不再自动加重，建议尽快就医或做运动医学评估。照顾自己最重要。`（COPY.redFlagText）
- **下肢进阶锁定**：练前膝痛 ≥3、本 session 有红旗、或 **28 天内**存在红旗 session（recentRedFlag）任一成立时，「下次训练建议」中下肢动作的 add/bodyweightUp 一律改写为保持文案（`膝部保护中：下肢先不加重，保持当前重量/次数就好。`）。
- 膝注意动作的固定提示（动作卡、动作库详情、执行页膝痛≥3 时 alert 条）：`膝部小贴士：箱式深蹲和分腿蹲以「不痛」为准，大腿平不平行地面不重要；膝盖跟着脚尖方向走；分腿蹲可以单手扶东西。`

### 6.5 周报计算（computeWeeklyReview，进展页与导出共用）

输入 sessions + 本周起始日期 + plannedDays（= 排期训练日数）。返回 7 块：

1. **计划 vs 实际**：planned = 排期训练日数（动态分母，E13）；completed / partial / skipped 分别统计状态为 已完成 / 部分完成 / 已跳过 的 session 数。
2. **力量动作最近表现**：本周期内每动作最后一次执行的最大重量、组数/总次数，以及与首次的变化（+Xkg）。
3. **加重 / 保持 / 减量（建议）**：对最近出现过的动作逐一用 6.3 生成建议，归类为 加重/进阶 | 保持 | 减量（橙角标），附原因文案。
4. **有氧**：总分钟数 + 各器械分布（跑步机/椭圆仪/登山机）。
5. **膝部**：疼痛趋势（日期→分）；期间有红旗则置顶深红警告块。
6. **恢复观察**：平均睡眠 / 平均精力 + 观察性描述（睡眠≥7h 的训练中完成次数 vs 周完成数；**明确标注“仅为观察描述，不代表因果关系”**；少于 2 次睡眠记录则只报完成数）。
7. **下周建议（最多 3 条）**：按优先级——命中红旗 → 膝痛≥3 → 跳过≥2 次 → 平均睡眠<6.5 → 有可进阶动作 → 兜底「一切顺利」。文案见 9.4 COPY.nextWeek。

## 7. 数据模型与本地存储（db.js）

### 7.1 IndexedDB 结构

数据库 `fitness-workbench`，版本 1，5 个 object store：

| store | keyPath | 说明 |
|---|---|---|
| profile | 固定键 "me" | 用户档案（单用户） |
| sessions | id（uuid） | 每次训练会话 |
| measurements | id（uuid） | 身体测量（体重/围度） |
| photos | id（uuid） | 体态照片 Blob（**仅存本地，不进 JSON 备份**） |
| settings | 固定键 "app" | 应用设置与最近备份时间 |

### 7.2 profile（键 "me"）

`{ birthYear, sex('female'|'male'|'other'), heightCm, weightKg 不入档(见测量), primaryGoal(goalId), experience('experienced'|'restart'), kneeNote('none'|'left'),  schedule:{mon..sun: 'strength'|'cardio'|'rest'}, chosenStartDate:'YYYY-MM-DD'(第1周周一), createdAt, updatedAt }`

> 兼容：旧档案无 schedule 时启动兜底写入默认 5 天排期；V1.2 不新增 days 字段——天数 = schedule 中非 rest 的天数（天然自洽，历史数据零迁移）。

### 7.3 settings（键 "app"）

默认值：`{ restTimerDefault:90, weightIncrement:2.5, lastPhotoExportAt:null, lastBackupAt:null, schemaVersion:'1.0', rirHelpShown:false, ignoredAdvice:[] }`。

### 7.4 session（训练会话，核心实体）

```
{ id, date:'YYYY-MM-DD', templateId:'strengthA|strengthB|tuesday|thursday|posture',
  weekIndex(1..8), dayType(模板 dayLabel),
  mode:'standard'|'short',           // short = 25 分钟精简
  status:'进行中'|'已完成'|'部分完成'|'已跳过',
  readiness:{ sleepHours, energy1to5, fatigue1to5, kneePain0to10, sore, note } | null,
  planExercises:[{ exerciseId, reps:[min,max], sets, rir, rest, main, perSide, timed }],
  appliedAdvice:[], ignoredAdvice:[],   // 建议接受/忽略留痕（id 列表）
  exercises:[{ exerciseId, substituted?:true, substitutedTo?, sets:[{setIndex,plannedReps,weightKg,reps,rir}], painNote, painDuring?, anomalyNote?, redFlags?[] }],
  cardio:null | { machine, minutes, rpe, speed?, level? },   // 有氧日
  postFeedback:null | { difficulty1to5, kneeChange:'same|better|worse', completed:bool, redFlags[] },
  createdAt, updatedAt }
```

### 7.5 measurements / photos

- measurements：`{ id, date, weightKg, waistCm?, hipCm?, thighCm? }`（首次建档写入首条）。
- photos：`{ id, date, view:'front'|'side'|'back', blob:File/Blob, createdAt }`。

### 7.6 备份与导入

- **导出完整 JSON**（文件名 `fitness-workbench-backup-YYYY-MM-DD.json`）：`{ schemaVersion:'1.0', exportedAt, sourceDevice, profile, sessions, measurements, weeklyReviews(由 buildWeeklyReviews 计算) }`，**不含 photos**；导出成功即更新 settings.lastBackupAt。
- **导入**：仅接受 schemaVersion === '1.0' 且 sessions / measurements 为数组；**冲突不合并、导入即覆盖**（先清 sessions/measurements/profile 再写入，photos 不受影响），执行前二次确认弹窗（红色危险样式）：`将覆盖现有训练记录、测量与档案（照片不受影响）。确定继续？`
- **CSV 导出** ×3（UTF-8 BOM，文件名按日期）：训练组（date,template,exercise,set,weightKg,reps,rir,painNote）；有氧（date,machine,minutes,rpe,speed,level）；测量（date,weightKg,waistCm,hipCm,thighCm）。
- **导出照片 ZIP**（`fitness-photos-YYYY-MM-DD.zip`）：手写 STORED 无压缩 ZIP（local file header + central directory + EOCD，CRC32 自实现，零第三方库）；条目命名 `{date}_{view}_{id前8位}.png|jpg`；导出后更新 settings.lastPhotoExportAt。
- **照片备份轻提醒**：距离上次照片导出 ≥28 天（或建档起 ≥28 天）且存在照片时，「今天」页顶部黄条：`照片有阵子没备份啦，去「设置」导出个 ZIP 存好吧。`
- **清空全部数据**：连续两次危险确认（第二句文案：`请再次确认：删除后无法找回。建议先导出 JSON 与照片 ZIP。`）后 `clearAll` 并刷新页面。

## 8. 页面交互详规（app.js）

### 8.1 今天（today）

顶部卡片：日期 `YYYY-MM-DD ｜ 第 X / 8 周 · 阶段名`；大标题 = 当日模板（`💪 力量A` 等）或 `😴 今天休息`（休息日附 `好好休息也是训练的一部分，健身房外的活动咱们不记录。`）；右上类型徽章；🔥 连续天数 ≥2 时显示黄色徽章（连续完成 = 已完成/部分完成 连续天数，今天未练不视为断签）。

- **休息日**：无训练入口，返回。
- **有训练日**：若同日同模板已有记录则显示完成态（✅ 今日训练完成 / 已记录 + 难度 + 下次建议）；否则显示「上次同模板（日期）」摘要（前 3 个动作 `名称 重量kg×首组次数`）→ 主按钮「开始训练」（两次点击内可达，AC-02）→ 副按钮「🧘 单独做体态小训练（8–10 分钟）」；`thursday` 模板另有黄条「特别累的话，今天休息也完全没问题」+「😴 今天休息」（确认后写一条 status=已跳过 的 session）。
- **完成训练后**：若本 session 有红旗先弹红旗页；状态=已完成则触发 ✅ 庆祝全屏动效（文案 `今天也辛苦了，干得漂亮！`，震动 [80,60,80]）后再回今日页。
- **毕业卡**：第 8 周排期内所有训练日均存在「已完成」记录时，今日页顶部展示奶油毕业卡：`🎓 恭喜毕业！8 周计划全部完成，这段坚持真的太棒了！想再来的话，去「设置」重新开始新周期就好。`

**训练流程四步（底部弹层/内嵌切换）**：

1. **练前状态**（弹层表单）：睡眠小时（step 0.5，0–14，可空）、精力 1–5（默认3）、疲劳 1–5（默认3）、膝部疼痛 0–10（默认0）、明显全身酸痛 checkbox、备注（可选）。
2. **建议卡**（按 6.2）：逐卡「接受 / 忽略」。
3. **执行页**：顶部标题 + 模式徽章（标准 60 分钟 / 精简模式 25 分钟）+「结束训练」；膝痛≥3 时顶部膝部贴士条。有氧日先出「🚶 有氧卡」（器械三选一、持续时间*、主观强度 1–10*、速度/坡度阻力选填、说话测试提示）。力量/体态动作卡：动作名 +（膝部注意角标）+「替换」按钮 + 计划行（`计划 N 组 × a–b 次(或秒)（每侧）｜ 目标 RIR x ｜ 休息 Ns`）+ 逐组录入行（第 N 组 / 重量kg（自重动作可空选填）/ 次数或秒 / RIR 下拉）+「保存该动作」+「休息 Ns」按钮（倒计时结束震动 [200,100,200,100,300] + 全屏跳秒）+「动作异常反馈」。
   - 替换：弹层列出 SUBSTITUTES，选中后本动作 exerciseId 改写、记录 substituted=true + substitutedTo；替换后同动作历史合并计算。
   - 动作异常反馈：疼痛 0–10 + 说明 + 🛑 红旗自查五项勾选；保存后若勾红旗弹红旗页，若疼痛 ≥3 弹疼痛提示（`动作中疼痛≥3：建议减重、缩小幅度或替换动作（建议，非诊断）。`）。
   - 保存组支持快速改存（按钮短暂变为「已保存 ✓」）。
4. **练后反馈**：整体难度 1–5（默认3）、膝部变化（无变化/好转/加重）、完成状态（已完成/部分完成/已跳过）、🛑 红旗自查五项；「完成并生成摘要」→ 按状态进入 8.1 完成处理。

**下次训练建议卡**（今日页/完成后展示）：对计划内每个非有氧动作用 6.3 生成一条 `动作：建议文案`；命中 6.4 下肢锁定时改写为保持文案；顶部小字 `以下都是建议，不是诊断，你说了算。`

### 8.2 计划（plan）

- 顶部卡：标题「8 周计划」+ 当前周徽章（`第 X 周 / 共 8 周 · 阶段名`）+ 8 段进度条（<当前周=雾蓝实心，=当前周=深蓝，未来=浅灰）+ 切周导航（◀ 上一周 / 第 X 周 / 下一周 ▶，1–8 钳制，首尾禁用）。
- **7 天卡片网格**：每格=周几简写 + 类型 emoji + 一句话（`力量A · 60分`，分钟取模板 estMin 的"50–60 分钟"后段；有氧模板同规则；休息日灰显 `休息`）；当天缩放 1.08 + 阴影高亮；已完成（已完成/部分完成）盖 ✅。
- 下方卡片：💪 力量A / 力量B 动作清单（每行：名称+膝角标 ｜ 次数范围（/侧/s）· 周1→周8 组数 · RIR 首→尾 · 休息s）；🚶 有氧日两张卡（主体+折叠详情，注明 thursday 可休息）；📋 周期与补充卡（折叠：周期阶段说明 / 🧘 体态小训练明细 / 有氧器械顺序：椭圆仪前 4 周首选；跑步机快走为主；登山机第 5 周后可选手动）。
- **调整每周排期**（底部按钮，弹层）：顶部天数胶囊 2/3/4/5（当前高亮）；改天数 = confirm（`改成每周 N 天会按你的目标重新生成建议排期，当前的自定义调整会被覆盖，确定吗？`）→ 按 primaryGoal 重新生成；下方 7 天三态编辑器与计数提示同 onboarding；保存校验训练日数恰好 = 天数，保存后回到计划页。

### 8.3 进展（progress）

**本周周报卡（7 小节）**：标题 `本周周报（第 X 周）` + 🔥连续徽章；1 计划 vs 实际（计划 N 次 ｜ 完成 n ｜ 部分完成 n ｜ 跳过 n）；2 力量动作最近表现（每动作最近一次 最大重量kg+组数/总次数 与区间首尾差值 +Xkg）；3 加重/保持/减量建议（角标+原因）；4 有氧（总分钟与器械分布）；5 膝部（趋势序列 `MM-DD→分`，期间红旗置顶深红块）；6 恢复观察（平均睡眠 / 平均精力 / 观察性描述）；7 下周建议（≤3 条）→ 底部「🎨 生成分享卡」。

**分享卡（1080×1350 PNG，纯本地 Canvas 绘制，无网络依赖）**：奶油底 `#FAFAF7`；顶部 220px 抹茶绿条 `#7FB069` 白字「本周训练小结」+ 周标签；中部大数字 `完成N/计划N`（绿 `#5A8F4A`，200px 字重700）+ 灰字「本周完成训练」；`🔥 连续完成 X 天`（金 `#A87F1E`）；力量进步区（⭐ 力量进步 + 1–2 条 `动作 起始kg→最新kg`，绿色，取自 strengthHighlights：只取最大重量较区间首条有增长的前 2 条）；鼓励语（自动换行，正文色，见 6.5 分桶）；底部灰字 `个人健身训练工作台`。按钮：长按保存提示 +「下载 PNG」触发下载（文件名 week-{N}-share.png）。

**鼓励语语料（ENCOURAGE，4 桶 ×5 句，桶内随机）**：分桶判定——`done ≥ planned` → full（全勤）；`上周 completed === 0 且本周 done > 0` → back（断周回归，如 `欢迎回来！重新站上垫子的这一刻最难得。`）；`done ≥ 3` → most（如 `大多数时候都在场，这就是进步的样子。`）；否则 → few（如 `哪怕只来了一两次，也比停在原地强。`）。**默认不放体重、不放照片。**

**趋势卡**：每周训练次数折线（SVG 内联 path+circle，绿）；累计完成率 `X%（按每周 N 个训练日计）`（N=动态分母）；四个主项动作（哑铃高脚杯箱式深蹲 / 哑铃罗马尼亚硬拉 / 有支撑分腿蹲 / 上斜哑铃卧推）最大重量折线；体重周均值折线（按自然周聚合取均值，附文案 `体重建议每周测 3–7 次，看周均值趋势就好，单日波动不用管。`）。

**身体数据录入卡**：体重* + 腰围/臀围/大腿围（cm，选填），保存为当日 measurement。

**体态照片卡**：正面 / 侧面 / 背面三按钮 → 拍照/相册（file input）；同视角默认展示「最新一张 + 相隔 ≥26 天最近的一张」做 4 周对比（不足 26 天则显示最近 3 张）；说明 `只存本机，不进 JSON 备份。`

### 8.4 动作库（library）

检索支持关键字、训练日和器械类型。详情弹层展示名称、英文名、器械、部位提示、默认展开的动作要领、常见错误和加入今日训练按钮。

### 8.5 设置（settings）
